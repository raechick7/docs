An **Initiative** is a scoped, actionable project that sits inside a Strategy and represents a concrete workstream your team executes to move that Strategy forward. Where a Strategy answers *what* you want to achieve, an Initiative answers *how* you plan to get there — with a defined owner, a due date, and a set of milestones that make progress visible at every step.

## How Initiatives Relate to Strategies

Every Initiative belongs to exactly one Strategy. This relationship is intentional: it ensures that no project exists in a vacuum, and that every team member can trace their work back to a strategic priority. A single Strategy typically contains multiple Initiatives running in parallel or in sequence, each tackling a different dimension of the overall goal.

For example, a Strategy titled "Launch Product in the APAC Region" might contain Initiatives such as:

- Localize product interface and documentation
- Establish partnerships with regional resellers
- Build a regional customer support team
- Run an APAC-targeted launch campaign

Each of these Initiatives is distinct and independently ownable, but all contribute to the same strategic outcome.

## Initiative Fields

When you create an Initiative, you fill out a structured set of fields that define its scope and execution path:

| Field | Description |
|---|---|
| **Title** | A clear, action-oriented name for the project (e.g., "Localize Product Interface for Japanese Market"). |
| **Description** | A summary of the Initiative's goals, scope, and expected outcomes. |
| **Owner** | The individual or team responsible for driving the Initiative to completion. |
| **Due Date** | The target completion date. This is used to calculate progress and surface at-risk Initiatives. |
| **Priority** | The relative importance of this Initiative compared to others in the same Strategy (see Priority table below). |
| **Status** | The current execution state of the Initiative (see Status table below). |
| **Milestones** | Major checkpoints within the Initiative that break it into structured phases (e.g., "Beta complete," "User testing done"). |
| **Linked Metrics** | Quantitative measures attached to this Initiative to track whether it is achieving its intended impact. |

## Initiative Priority Levels

Use **Priority** to signal which Initiatives demand the most immediate attention and resource allocation.

| Priority | Description |
|---|---|
| **Critical** | Must be completed for the Strategy to succeed. Blocks or severely impacts other work if delayed. |
| **High** | Strongly contributes to the strategic outcome. Should be staffed and active before lower-priority work. |
| **Medium** | Important but not time-sensitive. Can be sequenced after Critical and High work is underway. |
| **Low** | Nice to have. Contributes value but will not materially affect the Strategy if deferred or descoped. |

## Initiative Status Values

Keep the **Status** field current so your team and stakeholders always have an accurate view of execution health.

| Status | Description |
|---|---|
| **Draft** | The Initiative is being scoped and has not yet been assigned or kicked off. |
| **Active** | Work is in progress. The Initiative has an owner and at least one milestone underway. |
| **Blocked** | Progress has stalled due to a dependency, decision, or external factor that needs to be resolved. |
| **On Hold** | Work has been intentionally paused, typically due to a reprioritization at the Strategy level. |
| **Completed** | All milestones have been achieved and the Initiative's goals have been met. |
| **Cancelled** | The Initiative has been discontinued and will not be completed. |

## Breaking Large Initiatives into Milestones

<Tip>
If an Initiative spans more than four to six weeks, break it into **Milestones** — named checkpoints that represent meaningful phase completions, not just calendar dates. Milestones keep large projects from becoming invisible between kickoff and delivery, give you clear moments to reassess scope and priority, and make it much easier to identify when an Initiative is falling behind before it's too late to recover.
</Tip>
